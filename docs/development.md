# Development

Requirements: Go ≥ 1.24, Node ≥ 22. Docker is optional (demo/production only).

## Fastest path (no Docker)

```bash
# terminal 1 – mock MUD (plain Telnet on :2323)
cd gateway && go run ./cmd/mockmud

# terminal 2 – gateway on :8080, allowing the Vite dev origin
cd gateway && GATEWAY_ALLOWED_ORIGINS=http://localhost:5173 \
  GATEWAY_UPSTREAMS=default=127.0.0.1:2323:plain GATEWAY_LOG_FORMAT=text go run ./cmd/gateway

# terminal 3 – frontend with hot reload; /ws is proxied to the gateway
cd frontend && npm install && npm run dev      # http://localhost:5173
```
Log in with any name and password. Try `help`, `look`, `n`, `colors`, `unicode`, `term`, `gmcp`, `hit`,
`flood 5000`, `crash`, `quit`.

## Docker demo

```bash
docker compose up --build        # then open http://localhost:8080
```
Starts mock MUD → gateway → frontend → Caddy edge. It never contacts dunemud.net.

## Tests

```bash
make test            # Go (race detector) + frontend unit tests + typecheck
make e2e             # real Chromium → vite preview → gateway → mock MUD  (starts everything itself)
make e2e-edge        # same suite through real Caddy (needs `caddy` on PATH)
```
Manually: `cd gateway && go test -race ./...`, `cd frontend && npm test`.

If Playwright cannot find its browser, point it at an installed Chromium:
`CHROMIUM_PATH=/path/to/chromium npm run e2e` (no `playwright install` needed).

Go tests that matter most: `internal/telnet` (fragmentation at **every** byte boundary, random
chunking, escaped IAC, overflow, negotiation loops), `internal/server` (end‑to‑end against the mock:
isolation, TLS failure modes, limits, backpressure, shutdown, password never logged). Frontend:
`ConnectionManager` with a fake socket, `SessionController` (masking/history), `GmcpStore`, React
`App` (states, input, history, inspector, prefs). E2E additionally runs under the production CSP and
fails on any violation.

### Live server probe (opt‑in)
See `docs/upstream-notes.md`. It is skipped unless `TELLWIRE_LIVE=1`.

## Configuration

All gateway settings are environment variables; the full annotated list is in
`gateway/.env.example`. Only `GATEWAY_ALLOWED_ORIGINS` is mandatory.
Frontend: optional `VITE_GATEWAY_URL` (default: same‑origin `/ws`).

### Testing TLS upstream locally
```bash
cd gateway
go run ./cmd/mockmud -tls -listen :2324 -cert-out /tmp/mock-ca.pem &
GATEWAY_UPSTREAM_CA_FILE=/tmp/mock-ca.pem GATEWAY_UPSTREAMS=default=localhost:2324:tls \
GATEWAY_ALLOWED_ORIGINS=http://localhost:5173 go run ./cmd/gateway
```
Without `GATEWAY_UPSTREAM_CA_FILE` the gateway refuses the self‑signed certificate and the browser
shows an `upstream_tls` error — that is the intended behaviour.

## Adding a GMCP package
Nothing to do in the gateway (it is generic). If the package is a *delta*, add its name to
`DEFAULT_DELTA_PACKAGES` in `frontend/src/gmcp/GmcpStore.ts`.

## README screenshots

Images in `docs/img/` are committed, not generated by the test suite.

```bash
cd frontend
npm run screenshots        # deterministic, from the mock MUD (2x desktop, mobile emulation)
npm run screenshots:live   # interactive, from a real MUD: you log in, press Enter per shot
```

`screenshots:live` defaults to `dunemud.net:6788` over TLS; set `UPSTREAM=host:port:tls|plain` to use another
server. It reads and stores no credentials. Before committing a live capture, check that no private chat, tells,
or other players' names are visible.
